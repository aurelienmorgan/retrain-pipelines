{#- SVG DAG rendering template. Inputs: `nodes` (task graph), `taskgroups`, `id_prefix`, `get_text_pixel_width()` (text measuring). Output: one interactive SVG per render -- task nodes (standard rect; parallel-entry and merge-exit trapezoids), taskgroup and parallel sub-DAG bounding rectangles, arrows, tooltips, interaction scripts. Model: - Containers own their content: each bounding-rect nests its whole subtree (underlays, rect, label, member nodes, nested containers, contained arrows); one group transform relocates the subtree. - Paint order is logical order: parents before children, content after its container rect, tooltips last in a canvas-level group. - Arrows never nest inside taskgroups; an arrow nests inside the innermost parallel region enclosing both endpoints, else renders at top level immediately following its source entity. Macros: - Shape: trapezoid_entry, trapezoid_exit, node_rect_box, collapse_expand_btn (one primitive each). - Entity: render_node, render_arrow, and dual-mode taskgroup_rect_box / parallel_rect_box. Rect mode draws a single bounding rect, allowing the full mode to render multiple underlays and the base container without duplicating rect attributes or infinitely recursing into content. Full mode renders the complete container and recurses into its content. Prepasses (compute only, emit nothing): 1. Node depths (DFS); parallel depth per node (+1 entering a region, -1 at its merge) -- drives bounds, regions, arrows. 2. Taskgroup nesting levels (iterative relaxation), parent links, top-level taskgroup resolution. 3. Parallel region discovery: per-region node lists, merge-to-region map. 4. Layout: per-depth Y padding (taskgroup chains summed, parallel regions maxed) for constant arrow length; centered X positions. 5. Bounds: taskgroup bounds (member-seeded, nesting-relaxed, tight inner margins, rect-center arrow axis); parallel region bounds. 6. X-centering: shift each top-level taskgroup's content so its rect center aligns with the midpoint of its outermost member node centers, compensating for the asymmetry introduced by nested taskgroup padding. 7. Containment: innermost region per node, region parent/root chains, region per top-level taskgroup; per-region content lists (direct nodes deduplicated: region lists hold each merge node twice). 8. Arrows: classification (one outgoing/incoming pair per top-level taskgroup or parallel region; remainder standard) and distribution (innermost common region, else source-entity anchor). 9. Render-time parallel depth per node: node rendering becomes order-independent. Render pass: one sweep over `nodes` in DAG order. Each node resolves to its top-level entity -- standalone node, root taskgroup, or root parallel region -- rendered exactly once; containers recurse into content (nested containers, arrows, taskgroups, direct nodes as applicable); entity-owned arrows follow their entity. Arrow attachment: in/out arrows always anchor at the rect center of the taskgroup or parallel they point to (middle of the bounding border), independent of the rect's width. This is computed identically at render time (center_x = (min_x+max_x)/2) and at reflow time (updateTaskgroupBounds / updateParallelBounds), so collapse-then-expand cycles restore the original anchor positions exactly. Scripts: External JS modules handle tooltip visibility, dragging, collapsing, magnifier, and canvas pan/zoom. They are loaded dynamically by replacing the `` marker. A small inline script initializes the `config` and `ctx` objects, resolving all Jinja-injected DOM IDs and layout constants, then calls the `initDag*` functions in strict order.
